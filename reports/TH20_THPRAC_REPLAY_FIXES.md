# TH20 回放不同步：thprac 的说明与修复方法

整理日期：2026-10-12。本文根据用户提供的 thprac 2.2.2.7 截图，以及本地 thprac 源码整理。说明采用中文归纳；不是截图逐字转录，也不表示当前回放的原因已经全部确认。

## 术语与结论

这里的“replay 爆炸”通常指回放与录制过程不同步：子弹、伤害、召唤、得分或掉残发生变化，不一定是程序崩溃。原版也存在这些问题，同一文件在不同机器、不同加载耗时或不同分辨率下可能表现不同。

| 类型 | 触发条件 | 修复思路 |
| --- | --- | --- |
| 主线换面不同步 | 部分计时器及伤害光环跨面保留，加载耗时与录制时不同 | 记录、恢复换面状态；旧回放必要时搜索计时偏移 |
| ANM 复用问题 | 动画对象再次使用时保留旧字段 | 完整初始化复用对象；已录入异常过程的回放可能无法恢复 |
| Extra 分辨率不同步 | 播放分辨率与录制时不同，影响妮娜四符 | 恢复相关动画精灵的录制时高度 |
| 超时异变敌不同步 | 召唤槽耗尽、光环消失后击杀异变敌 | 修复释放后访问；旧回放记录、指定每次击杀的结果 |

## 1. 主线：连续播放和保存同步数据

1. 在回放菜单选择需要修复的主线回放。
2. 从 Stage 1 开始连续播放，观察是否保持录制时的行为。
3. 完成最后一次关卡切换、确认同步后，用主线修复工具保存副本。
4. 修复副本包含各面的同步状态，之后可以从中间关卡开始播放。

保存前需要具有全部相关关卡的同步数据。中途开始、跳过关卡，或者播放本身已经不同步，都不能当作修复成功。

### 1.1 为什么还需要计时偏移

灵梦的扩散石使用 R2（生物赤红），或灵梦炸弹／Y1（黄色地心）子机的伤害光环跨面残留时，换面期间继续走时的状态会受到加载耗时影响。因此即使从 Stage 1 连续播放，也可能在第二面或更晚出现不同步。

操作方法：在发生不同步的关卡设置偏移，从前一面重新播放并经过该次切换；反复调整，直到行为符合录制过程。逐次完成各面，再保存修复副本。播放时不能随意切换修复模式，也不能修改已经过去的关卡偏移。

| 机制 | 搜索方法 | 注意 |
| --- | --- | --- |
| Y1 子机残留光环 | 按 3 帧周期，测试 0、1、2 三种余数 | 不是所有换面机制都只有三种候选 |
| 灵梦 R2 | 在 120 帧周期内搜索 | 需要找到该机制可用的相位 |
| 灵梦炸弹残留光环 | 寻找精确偏移 | 可能到 Boss 战中段、光环失效时才显出差异 |

thprac 建议第一次切换先试 10–35 帧，后续先试前次值附近 ±10 帧；这些只是搜索建议，不是保证或通用修复参数。第四面资源更多，偏移可能跳变。语言等 thcrap 补丁也可能增加加载延迟。

修复模式每次切换会保存状态。已完成 1→2 的修复后，可从第二面继续；若发现该数据错误，可回到第一面重新生成。建议另外记录找到的偏移，避免丢失。

### 1.2 源码实际保存的状态

`th20_transition_pre_loading` 在加载前取得 R2 计时器值；`th20_transition_desync_fixes` 在激活时保存或恢复：

- 灵梦 R2 射击计时器 `reimuR2Timer`。
- 被动召唤槽计时器 `passiveMeterTimer`。
- 四个黄石选项的角度和计时器 `yellow2CycleAngle`、`yellow2CycleTimer`。
- 跨面存活的伤害区域 `rogueDmgSrcs`，以及下一个伤害编号 `nextDmgID`。

恢复伤害区域时先删除现有区域，再分配和恢复记录，重新绑定游戏上下文；从中间关卡直接开始会补偿跳过的 30 帧过渡。源码内部还有各次切换的最小加载帧基数 `{39,40,49,43,44}`，故 UI 偏移不能简单理解为计时器的绝对值。

### 1.3 ANM 复用错误

该问题可以随机出现，并伴随画面损坏。thprac 的 `AnmVM_Reset_hook` 保存对象的池编号（原布局 `+0x4c4`），清零整个 `0x5e4` 字节动画对象，再恢复编号并调用原重置函数。它在多个动画初始化／复用入口替换原来的局部重置，阻止旧脚本状态、计时器、指针等泄漏到下一次使用。

这属于预防修复。若录制过程已经受随机复用错误影响，不能保证仅靠换面偏移恢复旧回放。

## 2. Extra：分辨率修复

不同分辨率可能导致 Extra 渡里妮娜第四张符卡“古老的光明会”回放不同步。

1. 选择 Extra 回放，打开 Extra 分辨率修复。
2. 指定可能的原始录制分辨率：640×480、960×720、或至少 1280×960。
3. 播放检查四符是否同步；可以先预览，不必先保存。
4. 找到正确选项后保存修复副本。播放期间不能修改该选项；未指定分辨率不能保存该修复。

源码没有通过缩放整张画面修复。`th20_fix_ex_rep_resolution` 只在第七面、精灵编号 288 且脚本编号 33 的相关动画设置后，记录或恢复其 `sprite_dims.y`。三档旧回放候选高度为 6、10、14，保存字段是 `resolutionSpriteHeight`。由此把影响玩法的精灵尺寸与当前显示分辨率分离。

这说明高分辨率移植必须检查“精灵尺寸被玩法读取”的路径，仅保证投影和页面缩放正确仍不够。

## 3. 过期异变石：准确说是“超时异变敌”

触发条件是召唤槽已经耗尽、异变敌的光环消失，随后仍击败该异变敌。thprac 说明可能出现五种结果：红、蓝、黄、绿对应等级提升，或不提升。

这种旧回放可能在录制者的机器上正常，在其他环境不同步；差异常在下一次召唤开始后显现。它不能与月石消弹崩溃直接画等号。

### 3.1 旧回放的修复操作

1. 选择回放，打开超时异变敌修复工具并启用显示。
2. 播放时工具按关卡统计超时异变敌击杀，并收集每次结果。计数只有在回放仍同步时才可靠。
3. 若发生不同步，停止播放后修改对应关卡、对应次序的结果；也可手动增加或删除条目。
4. 常见结果是提升原颜色等级；需要尝试替代结果时，优先检查“无”和“+红”。
5. 重播确认后保存副本。该数据可以与主线及 Extra 修复一起保存，使用相应工具的保存按钮。

播放中不能修改击杀结果。标记“已修复”也不等于验证通过；必须观察完整相关过程。

### 3.2 源码实现与新回放预防

`th20_fix_stone_timeout_use_after_freeA/B` 修复超时处理中的释放后访问。`th20_expired_summon_kill_desync_fix` 在回放中发现召唤对象已释放时，按当前关卡及击杀序号恢复 `expStoneColors` 记录的结果；没有对应记录时收集当次结果供工具调整，并递增计数。

新录制依赖生命周期修复保证结果稳定；旧回放则可能必须恢复当年实际出现的结果。二者不能混为一谈。

## 4. 当前工程的验证边界

- 原版在调试堆下读取已释放伤害区域，产生被填充的异常道具坐标：此前已经定位并验证。
- 本轮已加入 SDL 版本 ANM 完整初始化预防修复；12 组污染复用测试通过，整包编译通过。尚未进行完整回放验证。
- 本轮还定位到 `special_state/environment.cpp` 的敌人死亡回调捕获召唤记录引用，而超时会释放该记录。已改为保存颜色值，消除这条释放后访问；这不等于自动恢复旧回放当年出现的错误颜色。
- 尚未确认 `th20_01.rpy` 的后续不同步具体属于换面偏移、超时异变敌，还是其他原因。
- 旧回放缺少这些扩展状态时，不能凭空推断出录制时的加载延迟或击杀结果。
- 局部测试和前 6000 帧一致不能代表全回放一致；仪器采集结果也需要先验证可靠性。
